\# HeyBuddy: project context (read this first, every session)

\## What this is
HeyBuddy is a native macOS menu-bar app (Swift 5.9, AppKit, Swift Package, macOS 13+), inspired by "HeyClicky". It is an AI buddy that lives next to the user's cursor. The owner is a student engineer learning to code, building this for free. Explain things simply and give exact steps. Never assume prior knowledge.

\## End goal (the product vision)
1\. Hold Control+Option: it starts listening instantly and shows a blue animated pointer that follows the real cursor. Release to send. The user names the assistant during onboarding and can say "Hey \<name>".
2\. It captures the screen and sends transcript + screenshot + cursor-gesture info (circled, swept, or pointed at something; plus the Accessibility element under the cursor) to a vision LLM.
3\. TEACHING MODE: when the user wants to learn something, the AI explains out loud while the animated pointer flies across the screen and ANNOTATES the real content: circles, outlines, underlines, highlights, arrows, polygons, spotlights (dim everything except one bright area), numbered badges 1-2-3 for sequences. It must feel like a real human tutor drawing on the screen: smooth, meaningful, never random, never monotonous, perfectly synced to the spoken words, and it must never hide or black out the content underneath. Supports follow-up questions.
4\. TASK MODE: the user can say things like "create a new folder here and move these files into it" (while circling files). The AI plans steps (shell / AppleScript / open), the user approves them in a confirmation dialog, then they run. Long-term goal: a general think -> act -> observe agent loop so capabilities are not hardcoded.
5\. Voice out via AVSpeechSynthesizer.
6\. It must be FAST (first spoken word within about 2.5 s of key release), RELIABLE (never stuck, never silently stops listening) and run FREE: the user's own free Gemini API key, Apple on-device speech, no paid backend, no paid Apple developer account. A local Ollama vision model is a planned fallback.

\## Files (Sources/Buddy/)
main.swift (entry), AppDelegate.swift (menu bar, onboarding, permissions, hotkey, state, gesture detection, plan execution, action runner), Ears.swift (mic + SFSpeechRecognizer), Screen.swift (screenshot, Accessibility lookup), Overlay.swift (transparent full-screen click-through NSPanel with the pointer, rings, labels, annotations), Brain.swift (Gemini REST client, retries/fallback, plan model, history), BuddyLogger.swift (logging). Also build.sh (builds, bundles Buddy.app with Info.plist, ad-hoc signs, opens it), Package.swift. The code was edited by another AI tool (Antigravity) that hit its quota mid-work, so do NOT trust any description here over what the code actually does. Verify by reading.

\## How to run
In the project folder: chmod +x build.sh then ./build.sh (opens Buddy.app; a circle icon appears in the menu bar). To see logs, quit the app and run .build/release/Buddy in the terminal. Permissions (Microphone, Speech Recognition, Screen & System Audio Recording, Input Monitoring, Accessibility, Automation) are attributed to whichever app launched the binary (Buddy.app vs Terminal vs Xcode vs the editor). Rebuilding with ad-hoc signing can invalidate permissions. If the screenshot fails ("could not create image from display"), the cause is Screen Recording permission.

\## Hard rules
\- GEMINI MODELS: keep these exact names: gemini-3.8-flash, gemini-3.5-flash, gemini-3.1-flash-lite. They are valid in Oct 2026. Older 1.5 / 2.x names are retired. Never downgrade or rename them. \## Known problems and history
\- Intermittent "request took too long": caused by retrying the same overloaded model, short time budgets (watchdog shorter than network budget), and slow single-model fallback.
\- defer { finish() } in runRequest fired right after the AI answered, cancelling the presentation (pointer/annotations vanished). Verify whether this is fixed.
\- In real use annotations draw as a SOLID BLACK box with a pink border hiding the content (probably a CAShapeLayer with default opaque black fillColor). The highlight is nearly opaque and misplaced. A canned label leaked from the demo into output. The "Demo annotations" menu item draws at hard-coded random positions. These issues are tracked in the roadmap.
\- Gemini coordinates are approximate. Plan: snap to reality using Apple Vision OCR (text boxes) and Accessibility element frames; Gemini picks an "intent" (attention, read, click, sequence, region, compare) and the renderer chooses the shape.
\- Coordinate convention: Gemini normalized 0-1000, points [y,x], boxes [ymin,xmin,ymax,xmax]; AppKit origin is bottom-left, screenshot/Accessibility origin is top-left. Use ONE conversion function.

### Gemini reliability update (2026-10-28; source reviewed, app build blocked)

- The networking details in the earlier "Current state" bullets describe the prior implementation. Current code uses `GeminiClient.swift` for header-authenticated model discovery and bounded sequential generation, and `BrainNetworking.swift` for a validated JPEG+text payload and plan decoding. There are no startup generation tests or hedged requests.
- Preferred names remain `gemini-3.5-flash`, `gemini-3.8-flash`, `gemini-3.1-flash-lite`. Discovery follows `nextPageToken`, filters these names for `generateContent`, and caches results for six hours. The last model with a decoded plan is tried first in this process. The three names were checked against Google's model documentation for image input and structured output; the list endpoint itself does not advertise those capabilities.
- `GeminiKeyProvider` loads the existing UserDefaults key into memory at launch, normalizes input, and updates memory immediately on save. The prior silent Keychain migration remains. Every Gemini request uses `x-goog-api-key`; the key is not put into the URL or diagnostics. `AppDelegate` offers Health Check and Copy Diagnostics. Generation is tested only after the user explicitly chooses it.
- Generation has a 30-second budget including discovery, at most three sequential attempts with 12-second per-attempt timeout, short jittered retry for transient errors, and per-model cooldown. `AppDelegate` cancels the old task on interruption and uses an interaction generation number to reject stale results. Typed errors distinguish key, permission, request format, quota/rate, overload, transport, and response failures.
- `Package.swift` now includes a test target with mocked Gemini HTTP tests. A syntax parse succeeded, but `swift build -c release` failed before compiling source because the sandbox denies the Clang module cache and the installed Swift compiler/SDK builds differ. Tests and live API behavior remain unverified until a compatible Mac build runs.

### Drawing engine update (2026-10-29; source reviewed, app build blocked)

- `DrawingElements.swift` defines validated top-left normalized `{x,y}` points and `{x,y,width,height}` rectangles, typed geometry, style, order, optional target/purpose, and a lossy decoder so one malformed drawing does not discard speech or other drawings. The previous `[y,x]`/`box_2d` annotations remain accepted through conversion.
